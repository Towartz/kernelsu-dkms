# kernelsu-dkms (KernelSU-Next)

Arch Linux DKMS package for [KernelSU-Next](https://github.com/KernelSU-Next/KernelSU-Next) (`dev` branch), with `CONFIG_KSU_NON_ANDROID` and `CONFIG_KSU_SELINUX` ported for container environments such as Waydroid.

This `kernelsu-next` branch is adapted from the `master` branch (`https://aur.archlinux.org/kernelsu-dkms` fork) to build the KernelSU-Next kernel module and `ksuinit` loader.

## Contents

The package builds `userspace/ksuinit` with Cargo and installs the kernel module sources for DKMS:

- `/usr/src/kernelsu-<pkgver>/`: KernelSU kernel module source, `Makefile`, and `dkms.conf`
- `/etc/modprobe.d/00-kernelsu.conf`: defines `alias ksu kernelsu`
- `/usr/bin/kernelsu-loader`: compiled `ksuinit` binary
- `/usr/bin/load-kernelsu`: helper script that ensures `ext4` is loaded, locates `kernelsu.ko*` for the running kernel, and streams it to `modloader -`

## Dependencies

- Runtime: `dkms`
- Optional: `modloader` (required by `/usr/bin/load-kernelsu`)
- Build: `git`, `rust`, `cargo`, and kernel headers for the target kernel

## DKMS Build Configuration

`0001-Patch-KernelSU-Next-for-dkms-and-waydroid.patch` ports `CONFIG_KSU_NON_ANDROID` and `CONFIG_KSU_SELINUX` to KernelSU-Next and updates `kernel/Kbuild` so DKMS uses the `KSU_GIT_VERSION` and `KSU_GIT_TAG` recorded during packaging.

`dkms.conf` invokes `make` with the following module options:

```text
KBUILD_MODPOST_WARN=1
CONFIG_KSU_X86_PATCH_SYSCALL_DISPATCHER=y
CONFIG_KSU_NON_ANDROID=y
CONFIG_KSU_SELINUX=n
CONFIG_KSU_DEBUG=n
```

For kernels built with Clang/LLVM, Arch Linux's `dkms` wrapper automatically passes `LLVM=1` when building modules.

## Building and Installing

```bash
git clone -b kernelsu-next https://github.com/Towartz/kernelsu-dkms.git
cd kernelsu-dkms
./install.sh
```

`./install.sh` installs `modloader` from the AUR if it is not already present (using `paru`, `yay`, or a temporary `makepkg` clone), stops any active Waydroid session/container, builds and installs `kernelsu-dkms` via `makepkg -sfi --noconfirm`, rebuilds the DKMS module for the running kernel, and extracts `kernelsu.ko` to `/usr/lib/modules/$(uname -r)/extra/kernelsu.ko`.

### Spoofed / Custom Manager APKs

By default, KernelSU-Next uses its standard manager signature (`0x3e6`). For a spoofed KernelSU-Next APK (or any custom manager APK), pass `--apk` to extract the v2/v3 signing certificate size and SHA-256 hash automatically, and `--pkg` to set `KSU_MANAGER_PACKAGE`:

```bash
./install.sh --apk /path/to/KernelSU_Next-spoofed.apk --pkg <spoofed.package.name>
```

`makepkg` uses the custom `DLAGENTS` helper generated by `PKGBUILD` to shallow-clone `KernelSU-Next/KernelSU-Next` (`dev` branch) and reads tags for `pkgver()`.

### Manual DKMS Rebuild

If you need to rebuild the DKMS module manually for the running kernel:

```bash
waydroid session stop
sudo systemctl stop waydroid-container

sudo dkms remove kernelsu/<pkgver> --all
sudo dkms add kernelsu/<pkgver>
sudo dkms install kernelsu/<pkgver> -k "$(uname -r)"

sudo mkdir -p "/usr/lib/modules/$(uname -r)/extra"
sudo zstd -d -f "/usr/lib/modules/$(uname -r)/updates/dkms/kernelsu.ko.zst" -o "/usr/lib/modules/$(uname -r)/extra/kernelsu.ko"
```

## Loading the Module

`kernelsu.ko` references unexported kernel symbols (such as `kallsyms_lookup` and `path_umount`), so standard `modprobe kernelsu` will fail with `Unknown symbol` on stock kernels.

Use `load-kernelsu` (which pipes the module through `modloader` to resolve unexported symbols; pass `-d` or `--unload-first` to unload an existing `kernelsu` module first):

```bash
sudo load-kernelsu
sudo load-kernelsu --unload-first
```
