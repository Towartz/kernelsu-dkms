# kernelsu-dkms

Arch Linux DKMS package for [KernelSU](https://github.com/supechicken/KernelSU) (`waydroid-experimental` branch), targeting container environments such as Waydroid.

This repository is a fork of the AUR package `https://aur.archlinux.org/kernelsu-dkms` with a `PKGBUILD` fix for `load-kernelsu.in` path resolution during `package()`.

## Contents

The package builds `userspace/ksuinit` with Cargo and installs the kernel module sources for DKMS:

- `/usr/src/kernelsu-<pkgver>/`: KernelSU kernel module source, `Makefile`, and `dkms.conf`
- `/etc/modprobe.d/00-kernelsu.conf`: defines `alias ksu kernelsu`
- `/usr/bin/kernelsu-loader`: compiled `ksuinit` binary
- `/usr/bin/load-kernelsu`: helper script that ensures `ext4` is loaded, locates `kernelsu.ko*` for the running kernel, and streams it to `modloader -`

## Dependencies

- Runtime: `dkms`
- Optional: `modloader` (required by `/usr/bin/load-kernelsu`)
- Build: `git`, `rust`, `cargo`, and kernel headers for the target kernel

## DKMS Build Configuration

`0001-Patch-Kbuild-for-dkms.patch` comments out git repository detection in `kernel/Kbuild` and sets `KSU_GIT_VERSION_VALID := 1` so DKMS uses the `KSU_GIT_VERSION` recorded during packaging.

`dkms.conf` invokes `make` with the following module options:

```text
KBUILD_MODPOST_WARN=1
CONFIG_KSU_X86_PATCH_SYSCALL_DISPATCHER=y
CONFIG_KSU_NON_ANDROID=y
CONFIG_KSU_SELINUX=n
CONFIG_KSU_DEBUG=n
```

For kernels built with Clang/LLVM, Arch Linux's `dkms` wrapper automatically passes `LLVM=1` when building modules.

## Building and Installing

```bash
git clone https://github.com/Towartz/kernelsu-dkms.git
cd kernelsu-dkms
./install.sh
```

Or run `makepkg -si` directly. `makepkg` uses the custom `DLAGENTS` helper generated by `PKGBUILD` to shallow-clone the upstream KernelSU branch, then fetches tags from `https://github.com/tiann/kernelsu.git` in `pkgver()` to compute the package version.

## Loading the Module

Load via `modprobe`:

```bash
sudo modprobe kernelsu
```

Or load via `modloader` using `load-kernelsu` (pass `-d` or `--unload-first` to unload an existing `kernelsu` module first):

```bash
sudo load-kernelsu
sudo load-kernelsu --unload-first
```
